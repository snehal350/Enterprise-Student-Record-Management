# Non-Functional Requirements Specification (NFRS)

## 1. Security
The system should authenticate users and restrict access to authorized information.

## 2. Usability
The interface should be simple, consistent, and understandable for students, faculty, and administrators.

## 3. Reliability
The system should maintain accurate records and handle errors without unnecessary data loss.

## 4. Performance
Common operations, including record retrieval and report generation, should complete within acceptable response times under the expected workload.

## 5. Scalability
The architecture should support future growth in student numbers and academic records.

## 6. Maintainability
The software should be organized into manageable modules to simplify updates and troubleshooting.

## 7. Data Integrity
The system should validate entered information and prevent inconsistent or incomplete records where required.

## 8. Privacy
Student information should be handled according to institutional policies and applicable data protection requirements.

## 9. Availability
The system should be available when required for routine academic activities, subject to planned maintenance.
